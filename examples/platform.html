1mg AgentOS v4
1mg AgentOS — The Vision
An Agent Operating System built on the LangChain/LangGraph ecosystem. Minimal dependencies, modular design, scalable architecture. Two repositories: Python backend (agents + skills + integrations) and TypeScript frontend (chat + approvals + dashboard). The platform comes to the employee — chat-first, zero-form approvals, proactive briefings.

Design Principles: Less Is More

Minimal stack: LangGraph for agents + orchestration + durable execution, APScheduler for cron triggers, Qdrant for vectors, MLflow for observability, PostgreSQL for state, Redis for LangGraph checkpointing. No unnecessary abstractions.

Employee-first: Chat window as primary interface. Inline approval cards — one click, not forms. Morning briefing via email. Employee Context Engine personalizes every interaction. The system knows who you are.

Two repos: agentos-backend (Python — FastAPI + LangGraph + skills) and agentos-frontend (TypeScript — Next.js + React). Clean separation. Both scalable independently.

💬 Chat-First Interface

Employees interact through natural language. "What's pending?" "Process Cipla invoices." Agent responds with context-aware answers and inline approval cards. No dashboard navigation needed for daily work.

🧠 LangGraph Agents

Department agents built as LangGraph StateGraphs. Shared state for inter-agent communication — no event bus. Checkpointed to Redis. LangGraph IS the workflow engine — handles orchestration, retries, HITL, durable execution.

📦 Skill Library

40 tested, versioned business logic units. Each skill defines its LLM boundary — deterministic math stays in code, LLM handles only judgment. Skills are Python modules with pre/post validations and eval suites.

👤 Employee Context

Auto-built profile for each employee from Darwinbox, SAP, platform history, Google Workspace. Powers personalized chat, zero-form approvals, and proactive briefings. The system knows your role, patterns, and shortcuts.

📊 MLflow Observability

One-line mlflow.langchain.autolog() traces every agent decision, tool call, and cost. Eval judges for anomaly detection and quality scoring. Replaces the need for a separate Inspector Agent.

🔒 Audit-First

Every agent action traced via MLflow. Full reasoning chain logged. RBAC per agent. Pharma-grade compliance trail. Dedicated Audit Trail view for end-to-end decision tracing.

LangGraph IS the Workflow Engine

No Hatchet. No Temporal. No Celery. LangGraph handles agent orchestration, state management, retries, crash recovery (via RedisSaver checkpointing), and HITL pauses (via native interrupt()). APScheduler only answers "when to start things" — async-native, PostgreSQL job store, no separate server. This is the simplest production stack: LangGraph + APScheduler + FastAPI.

Agent Flow: Invoice Processing
End-to-end through the 4-ring architecture. Shows which ring handles each step and where the LLM boundary sits.

1. Trigger Ring 0

Gmail API detects invoice email. APScheduler triggers workflow. LangGraph checkpoints initial state to Redis.

2. Agent Activation Ring 2

Finance Agent graph starts. LLM reads email metadata, selects "Invoice 3-Way Match" skill. Permission check passes. MLflow autolog traces every step.

3. Parse Invoice Ring 3 — Skill

PyMuPDF extracts text + pdfplumber extracts tables. Deterministic. If format is novel/scanned, LLM assists with layout understanding.

4. 3-Way Match Ring 3 — Skill

Query SAP for PO + GRN. Compare amounts (Python math). Validate GST (deterministic calculator). No LLM needed.

5. Knowledge Lookup Ring 1

LangChain retriever queries Qdrant for vendor history. PostgreSQL for compliance score and decision memory. Employee Context for reviewer's approval patterns. Confidence Engine checks autonomy level.

6. LLM Judgment Ring 2

LLM involved. "Discrepancy is 0.4% on trusted vendor. Confidence 97%. Auto-approve 9 items, flag 1 new HSN code for human review."

7. Human Gate interrupt()

LangGraph interrupt() pauses graph. Inline approval card appears in chat: 3-line summary + confidence badge + expand for details. One click to approve/reject. No form, no navigation.

8. Execute & Log Ring 3 + Ring 0

SAP tool creates MIRO. Gmail notifies vendor. MLflow logs full trace with cost. Decision Memory stores human override (if any). Confidence Engine updates score.

Autonomy Levels

Level 0 — Full Human

Every action verified via inline approval card. Starting state. interrupt() on every execution. First 50 instances reviewed.

Level 1 — Low Risk Auto

Auto-approve: amount < threshold, trusted entity, <1% discrepancy. MLflow monitors for anomalies. After 95% match rate over 50+ instances.

Level 2 — Mostly Autonomous

80-90% auto-processed. Humans see edge cases + new entities only. MLflow eval judges validate outputs continuously. Pattern Learning suggests automation rules.

Level 3 — Autonomous + Audit

Agent handles end-to-end. MLflow anomaly detection flags issues. Human does weekly sample review. Full audit trail in MLflow + PostgreSQL. Employee controls via Automations panel.

MLflow Replaces Inspector Agent

mlflow.langchain.autolog() captures every decision, tool call, cost, and latency. MLflow evaluation judges run post-execution: hallucination detection, relevance scoring, cost anomaly alerts. Custom eval judges check business rules ("does amount balance?", "is GST valid?"). No separate Inspector Agent needed — observability + eval judges + alerting covers it.

What We Dropped (and Why)

Hatchet / Temporal → LangGraph + APScheduler: LangGraph IS the workflow engine. APScheduler for cron. No separate orchestrator.
Celery → APScheduler + FastAPI BackgroundTasks: Celery is sync-first. Our stack is async end-to-end.
Qdrant → distributed Qdrant: Upgrade path when you hit 500M+ vectors or need multi-region.
MLflow → LangSmith: If you need LangChain-native alerting and enterprise compliance features.
PyMuPDF → Docling: When 10%+ of documents fail with basic parsing.
Direct APIs → Composio: When you integrate 5+ external services and need unified auth.
PostgreSQL ontology → Neo4j: When entity relationship queries become complex (multi-hop reasoning).

Edge Cases & Resilience
Production failure modes and how the architecture handles them.

Agent-to-Agent Failures

Problem: Finance needs Supply Chain data. Agent node fails or returns garbage.

Solution: LangGraph's shared state + conditional edges. If a node fails: retry 3x (LangGraph retry logic), then write error to shared state. Supervisor reads error, routes to fallback (cached data or human escalation). MLflow traces the failure for debugging.

Stale Data Problem

Problem: Agent reads bank balance, human approves later, balance changed.

Solution: "Data Freshness Check" skill. For financial writes: mandatory re-read before execution. If changed → pause, recalculate, re-present to human via inline approval card. Configurable staleness threshold per operation.

Multi-Warehouse Coordination

Problem: WH-A has surplus, WH-B has shortage. Without holistic view, B orders new stock.

Solution: Supply Chain Agent's shared state includes all 28 warehouses. "Multi-Warehouse Transfer" skill checks surplus before any PO generation. Compares transfer cost vs new PO cost.

Hallucination Cascade

Problem: Agent hallucinates a drug SKU → cascades into wrong PO, pricing, inventory.

Solution: Skill postcondition validations. "Does SKU exist in drug master?" Deterministic validators, not LLM. MLflow eval judges check outputs. Financial math never through LLM.

Schema Drift

Problem: SAP BAPI response format changes. Agent parses wrong data silently.

Solution: "Schema Drift Detection" skill. Daily canary tests call each integration with known data, validate response shape. On drift: alert + pause affected workflows. APScheduler cron job.

Model Degradation

Problem: LLM provider updates model. Parsing quality drops.

Solution: Model pinning per skill. MLflow eval suite runs on every model change before promotion. Shadow mode: compare old vs new model outputs. Promote only on eval pass.
